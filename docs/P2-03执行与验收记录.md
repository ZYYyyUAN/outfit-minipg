## 失败定位与最小修正

前两次本机输入未满足8～64字符限制，在派生密码、BEGIN、分配ID及复制之前拒绝，相关失败轮次保留。随后在本机提示中增加长度反馈和重输，仍不记录实际输入。没有用替代密码继续。

正式COMMIT后第一次核对失败，原因是核对器按计划文字假设10月7、8日均有实际日记；重新检查源数据和数据库发现只有7日，8日为零篇。**这是计划与固定样例之间的差异，不是导入漏记。** 未补造日记或修改日期。最小修订为：数据库SELECT构造两个DATE边界值，对实际窗口谓词核对0/1，同时关联统计当天真实日记数1/0；完整NOT EXISTS仍查询正式日记。V18按此明确修订完成，不能将结果表述为存在一篇8日日记。

为修正后续检查增加--resume/-ResumeRun，直接核对既有COMMIT并验证重复拒绝，跳过首次导入及回滚写入。其后20项离线测试重新通过，核对器在真实数据库重跑通过。写入核心seed-demo、demo-common、password、schema、锁文件及旧结构函数版本与实际回滚/COMMIT轮次完全相同；变化仅为核对边界和本机编排入口。最终verify及验收汇总绑定当前全部实现校验值；没有为了凑“同版本”清库重演。

```powershell
$env:DB_HOST = '127.0.0.1'
$env:DB_PORT = '3306'
$env:DB_USER = 'root'
$env:DB_NAME = 'wardrobe_demo'
$dbSecret = Read-Host 'MySQL password' -AsSecureString
$demoSecret = Read-Host 'Demo password' -AsSecureString
$dbPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($dbSecret)
$demoPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($demoSecret)
try {
    $env:DB_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($dbPtr)
    $env:DEMO_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($demoPtr)
    node database/verify-demo.mjs --run '<正式导入runId>' --as-of 2026-11-06
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($dbPtr)
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($demoPtr)
    $dbSecret.Dispose()
    $demoSecret.Dispose()
    Remove-Item Env:DB_PASSWORD, Env:DEMO_PASSWORD -ErrorAction SilentlyContinue
}
```
