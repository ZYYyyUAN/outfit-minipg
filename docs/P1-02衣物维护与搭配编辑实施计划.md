## 2. 视图、入口与返回行为

### 2.1 六个视图的实施内容

| 视图 | 内容与主要操作 | 入口、保存及返回 |
| --- | --- | --- |
| 衣橱列表 | 保留名称、分类筛选；增加新增衣物、在用/已归档/全部切换；数量来自工作数据当前范围 | tab进入；点单品进入衣物详情，记录列表筛选及滚动位置；新增进入空表单 |
| 衣物详情 | 完整图片、名称、分类、颜色、季节、备注、归档标记；从现有日记计算穿着次数、最近日期；相关搭配和已有穿着日期 | 可编辑、归档/恢复；相关搭配可进入搭配详情；返回恢复来源视图及位置 |
| 衣物新增/编辑 | 图片、名称、分类、颜色、季节、备注；保存与取消；编辑预填已有值 | 新建成功进入新衣物详情；编辑成功返回同件详情；取消返回进入表单前视图 |
| 搭配列表 | 保留场景筛选和真实2×2预览；增加新增搭配、归档范围；超过4件仍标完整数量 | tab进入；组合行进入搭配详情；新增进入空表单 |
| 搭配详情 | 名称、场景、备注、归档标记；全部有序单品及各单品归档状态 | 可编辑、归档/恢复，点单品进入衣物详情；不提供记录穿着按钮 |
| 搭配新增/编辑 | 名称、场景、备注、已选单品、数量、上移/下移、移除、选择衣物、保存与取消 | 多选面板确定只改父草稿；保存成功进入该搭配详情；编辑预填完整顺序 |

衣物详情的相关穿着日期只读列出日期及场景，不放尚未接通的日记详情跳转。已有日记继续从日记tab查看摘要，避免提前实施P1-03。

空列表区分“没有在用衣物/搭配”“没有已归档项”和“筛选无结果”。在用列表真正为空时提供新增入口；已归档空态说明暂无归档；筛选无结果提供清除筛选。清除搜索只清名称，清除筛选同时重置查询及分类/场景，但保留用户选择的归档范围。

### 2.2 导航栈与返回约定

4个根入口仍为衣橱、搭配、日记、我的，根页的筛选、月份、日期和滚动各自保留。子视图通过统一显示区域呈现，页头变为返回按钮和具体标题，底部tab隐藏；只读详情间可压入下一帧，返回逐层弹出。打开表单时保存来源帧，提交成功用目标详情替换表单帧，返回不再掉进已经保存的旧表单。

从列表直接新增时，栈关系为“列表→新增表单”，保存后变成“列表→新记录详情”。从详情编辑时，保存后仍回到原详情，不重复压入一份同件详情。归档/恢复后保留详情，返回时按原列表归档范围重新计算结果。

只读详情之间的跳转保留各自内容滚动。列表返回保留筛选及原滚动值；数据变化使内容变短时，浏览器自然限制到合法位置。改变筛选或归档范围时回列表顶部。新增保存后不悄悄清掉原筛选：目标详情始终能看见新记录，返回后若被原条件排除，仍按原条件显示。

本阶段不提供子视图深链接。应用内返回使用页头按钮；浏览器后退仍遵循浏览器页面历史，有脏草稿时通过离开提示保护输入，不伪造完整Web路由行为。

### 2.3 未保存与取消

- 编辑草稿建立时记录初始字段值、选定图片和衣物顺序。比较草稿与初始快照判定是否改变；改回原值后恢复为无改变状态。
- 无改变时返回/取消直接离开。有改变时提示“放弃未保存的修改？”；确认后释放该草稿新增的临时图片，回来源视图；拒绝则保持所有输入和当前滚动。
- 保存校验失败不离开，不改工作数据，不增加记录数，保留文字、图片和选择顺序。定位首个错误并显示字段提示。
- 多选面板的“取消”明确丢弃这次面板选择，父表单草稿保持原样，不再叠加一次放弃确认；Escape/遮罩关闭按取消处理。
- 浏览器刷新/关闭时只有脏表单注册beforeunload；浏览器原生文案由浏览器决定。完成保存或取消后撤销该提示。确认刷新后回到原始样例。

## 3. 衣物维护与图片流程

### 3.1 字段与校验

| 字段 | 新建初值 / 编辑预填 | 保存规则 |
| --- | --- | --- |
| 图片 | 新建无图片；编辑沿用当前imagePath | 必填；已通过选择入口校验的本地图片或现有图片均可；不能把文件名当有效图片 |
| 名称name | 新建空；编辑为当前名称 | 去首尾空白后1～40字符 |
| 分类categoryId | 新建未选；编辑为当前分类 | 7个固定分类之一，不默认塞入上装 |
| 颜色color | 新建空；编辑为当前颜色 | 去首尾空白后1～20字符，保留描述性颜色，不限制为固定色块 |
| 季节season | 新建未选；编辑为当前值 | 春、夏、秋、冬、春夏、春秋、秋冬、四季之一 |
| 备注note | 新建空字符串；编辑为当前备注 | 0～500字符，保留有意义换行；不强制填写 |

名称及颜色使用单行输入，季节和分类为明确选项，备注为多行。保存入口统一检查完整草稿一次；图片选择在进入草稿时校验一次，内部使用已确认图片。字段长度口径按字符计。显示错误时不通过裁切、默认值或保留旧值悄悄把非法输入改为成功。

表单显示字符数量提示，不用maxlength静默截断超长粘贴；超限文字保留在草稿，保存时显示对应错误。继续复用现有输出转义，用户录入的名称与备注按文字显示，不直接作为HTML插入。

新衣物的userId沿用演示资料ID，isArchived=false、origin=prototype由内存提交逻辑生成；编辑只改表单字段，保留ID、归档状态和已有关系，不物理删除。

### 3.2 本地选图

1. 用户通过本地文件选择器选1张JPEG/PNG；取消选择不改变当前图片。
2. 在选择入口检查类型、5MiB上限及浏览器可解码性。无效时显示原因，保留此前有效图片及其余字段。后台的文件真实性与归属校验留到业务实现阶段。
3. 为待选文件建立对象URL，显示完整图片；图片读取未完成时保存不可提交。读取成功后替换草稿的待提交图片。
4. 编辑没有重新选图时沿用旧imagePath，不重复生成对象URL；新建没有有效图片则不能保存。
5. 有效保存后，将草稿图片地址写入工作衣物；重新打开、加入搭配或查看已有日记均能看到当前图。没有HTTP上传请求，不写入assets或原始JSON。

图片区域提供“选择图片/更换图片”，不标成已经上传服务器。选图失败与图片缺失分别反馈；图片容器继续等比contain，原始长裙、鞋和帽轮廓不能裁断。

### 3.3 对象URL生命周期

用一个ownedObjectUrls集合登记本原型通过URL.createObjectURL创建的地址；源素材相对路径不进入集合。草稿临时地址与工作衣物已提交地址分开管理，不根据是否含文件名猜归属。

| 时机 | 地址处理 |
| --- | --- |
| 草稿重新选择另一张有效图片 | 新图确认可用后，释放上一张仅属该草稿的待提交地址；当前工作衣物旧图仍有效 |
| 无效文件或解码失败 | 释放本次新建但无效的地址，保留此前有效图片 |
| 放弃新增/编辑 | 释放该草稿新建且未提交的地址；不能释放原有工作记录正在使用的图片 |
| 保存新图 | 新地址交给工作记录持有；不是表单关闭时就释放 |
| 替换已提交的本地图 | 所有受影响视图重新读取新图后，释放不再被工作衣物或活动草稿引用的旧自有地址 |
| 只读详情返回、切tab、归档 | 不释放仍被工作衣物使用的地址 |
| 刷新、页面最终销毁 | 工作数据随页面销毁，由浏览器回收仍存在的对象资源；beforeunload只负责提示，不预先撤销图片，以免用户取消离开后预览失效 |

不把对象URL存入localStorage、sessionStorage、IndexedDB或源文件，不建设图片缓存、自动文件清理、base64存储或云图床。图像对象URL在本次页面生命期内可使用，不承诺复制到新窗口仍可恢复数据。

### 3.4 保存与跨入口刷新

成功保存前全部字段和图片就绪，再一次替换或新增工作记录；新增记录排到当前工作列表前部，源数组和既有记录顺序不改。成功后重建衣物索引、刷新对应列表、数量、相关搭配预览及当前日记摘要，再显示目标详情。

资料数量不得继续只在loadData时计算。衣物总量与分类数量来自当前工作数据及归档范围；“我的”显示未归档衣物数、未归档搭配数和日记篇数，并使用“在用衣物/在用搭配”等明确标签。基础样例仍为24/8/12。

## 4. 搭配编辑与衣物选择器

### 4.1 字段

| 字段 | 初值 | 保存规则 |
| --- | --- | --- |
| 名称name | 新建空；编辑原值 | 去首尾空白后1～40字符 |
| 场景occasion | 新建空；编辑原值 | 去首尾空白后1～20字符；支持已有场景快捷选择及填写新场景 |
| 备注note | 新建空字符串；编辑原值 | 0～500字符 |
| clothingIds | 新建空数组；编辑复制完整清单 | 1～20个有效字符串ID、无重复；均存在于当前工作衣物；数组顺序即展示顺序 |

字符串ID规则仅用于当前原型，真实HTTP接口仍按总方案使用数据库整数ID。不能把总方案“正整数ID”直接套到CLO001或TMP-CLO-0001，导致合法样例无法选择。

### 4.2 已选列表与排序

表单显示全部已选单品，不仅显示列表预览前4件；每行有完整缩略图、名称、归档标记、上移、下移和移除。首项上移、末项下移禁用并具有明确禁用状态，不显示拖拽把手或未实现的拖动功能。

上移/下移只交换相邻ID；移除只改搭配草稿，不归档或删除衣物。移除后数量立即更新。衣物重复点击不能重复加入；新增选择默认追加到已选末尾，不覆盖用户之前的排序。

### 4.3 多选面板

沿用现有dialog容器改为衣物选择面板，只有一个面板层级。顶栏标题与取消保持可见，底部显示已选数量及确定，中间网格独立滚动；本阶段不支持在选择器内直接新建衣物，避免套叠两个编辑草稿。

打开时，复制父表单clothingIds为pickerDraftIds。面板具有名称、分类筛选和“包含已归档”开关，默认只列在用衣物；已选区域始终列出完整选中结果，含不在当前筛选范围内或已归档的项。

切分类、搜索、切换是否包含归档，只改变候选网格，不清空pickerDraftIds；当前不可见的已选项仍计入数量，用户可在已选区移除。确定时按当前面板顺序替换父草稿数组，关闭面板但不保存搭配；取消、Escape和遮罩关闭都丢弃本次面板改动。父草稿与面板草稿都不得和工作搭配数组共享可变引用。

选择0件可确定回父表单，但父表单保存时必须提示至少选1件。达到20件后仍可取消已选项，未选项显示数量上限反馈，不能静默添加第21件；移除后可继续选择。

### 4.4 保存及重开

统一校验父表单字段与最终ID数组，通过后一次写入工作搭配。新增生成临时ID并置为未归档；编辑保留ID及原归档状态。clothingIds保存为独立数组，不能把父草稿或选择器的数组对象直接挂到工作数据。

成功后刷新搭配列表、场景选项、搭配详情、衣物详情中的相关搭配及我的数量。新场景立即出现在筛选选项；某场景不再有该范围内记录时选项随工作数据重算。为保持当前筛选，若当前选定场景已无记录，继续保留该当前选项并显示无结果；清除场景后恢复全部，不悄悄切换筛选。

## 5. 归档、恢复和历史关系

衣物和搭配均有在用/已归档/全部范围，默认在用。详情页根据当前状态提供“归档”或“恢复”；操作立即作用于工作数据，不删除，不自动改变另一类记录的归档状态。操作后停留详情，提示只在本次演示内生效，返回列表保留原筛选并重新计算内容。

归档衣物仍可在已归档范围找到、打开详情、编辑、恢复，也可通过选择器的包含开关加入搭配。已选归档衣物必须保留并带文字标记。归档搭配仍可在归档范围查看和编辑；不自动恢复；已有日记继续关联原来源ID。

| 变化 | 必须更新 | 必须保持 |
| --- | --- | --- |
| 衣物新增 | 当前范围列表、分类数量、选择器候选、我的在用衣物数 | 日记集合及日期、搭配原清单 |
| 衣物名称/图片/颜色等编辑 | 衣物详情、相关搭配所有出现位置、日记摘要中的同件衣物 | 衣物ID、搭配和日记的衣物集合及顺序；原日记附图photoPath |

## 6. 内存状态与代码改动安排

### 6.1 三层数据

| 层 | 生命周期与用途 | 写入约定 |
| --- | --- | --- |
| sourceData | fetch成功时读入的原始JSON，仅供初始化与刷新基线 | 不修改，不加入临时ID和blob地址 |
| workingData | 从sourceData做结构化复制，本次打开内共用 | 只有成功保存、归档和恢复会修改；日记数据本阶段只读 |
| 表单/选择器草稿 | 进入编辑时复制当前工作记录；离开时销毁 | 输入、移除、排序都只改草稿；确认选择器后仍未提交工作搭配 |

衣物索引和日记索引由workingData建立，保存衣物后重建衣物索引；日记日期索引保持原数据。分类只读共享。新增ID按实体分开计数：TMP-CLO-0001、TMP-CLO-0002与TMP-OUT-0001互不影响。取消草稿不产生记录，不消耗创建计数；编辑、归档不生成新ID。

刷新后重新fetch原JSON，临时记录、编辑、归档和本地图全部消失，回到衣橱默认范围、24件、8套、12篇和2026-11-05。界面资料说明改为“可在当前演示中维护衣物和搭配，刷新恢复样例”；日记仍只读。没有新的公共API、数据库schema或真正持久化数据格式。

### 6.2 需要新增的状态职责

- 导航：根入口、子视图栈及来源帧滚动；内部返回统一处理。
- 筛选：在用/归档/全部范围，延续名称、分类与场景状态；衣物选择器使用自己的条件。
- 表单：实体类型、创建/编辑模式、目标ID、初始快照、当前草稿、字段错误及保存状态。
- 图片：草稿待提交地址、读取状态及自有对象URL集合。
- 选择器：独立已选ID数组、候选筛选、包含归档开关。

这些是页面运行状态，不建立独立业务状态框架。保存时集中刷新真正受影响的区域；对隐藏根页面重绘前保留其滚动位置，重绘后恢复，不因编辑一件衣物重置日历月份或清掉另一页筛选。
