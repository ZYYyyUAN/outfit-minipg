### 2.3 导航帧与维护后的定位

沿用内存stack和单个subview，扩展明确的kind：clothing、outfit、diary、statistics；detail/edit区分仅用于有表单的实体。各kind明确分派，不再用“不是衣物就是搭配”的二分逻辑。帧保存kind、id、mode、scroll，统计月份作为独立状态；不引入路由库或URL深链接。

帧只保存ID和视图状态，返回时用最新data渲染，不保存旧日记对象、旧图片或汇总快照。根页面DOM保留；重绘前记录滚动并在重绘后恢复。只读详情之间返回恢复帧滚动。表单内打开选择器不重建父表单，确定、取消或看图关闭后保留表单位置。

| 动作 | 确定的状态与返回结果 |
| --- | --- |
| 从日历新增并保存 | 将表单帧替换为新日记详情；日历month/date同步到保存日期。详情返回即到该日期摘要 |
| 从搭配发起并保存 | `搭配详情→日记表单`变为`搭配详情→新日记详情`；日历在后台同步到新日期；返回仍回搭配详情，不强制切tab |
| 编辑保存、包含跨月改日期 | 撤去表单帧，回同ID日记详情，不再压一份相同详情；日历定位新日期。原日期标记移除、新日期标记出现；详情页重新从顶部展示保存结果 |
| 取消新增/编辑 | 不改变日历、统计月份、工作记录或数量；返回原帧和位置；没有改动时不弹确认 |
| 删除取消 | 不改变记录、帧、图片、选日或滚动 |
| 删除确认 | 清空子视图栈，切日记tab，日历定位被删记录原日期，显示无记录摘要及“记一笔”；不回到已删详情，也不保留指向它的旧返回帧 |
| 只读关联跳转 | 保留各来源帧滚动；不因查看另一篇日记而悄悄切日历月份 |
| 切tab或统计月份 | 根页状态各自保留；统计月份不影响其他指标的统计窗口 |

成功保存和删除只重置明确需要定位的日历滚动，衣橱/搭配的筛选、归档范围及滚动保持。底部tab在子视图隐藏，应用内页头返回是正常返回方式；浏览器后退依旧是浏览器历史，不伪装成完整Web路由。

## 3. 日记字段、草稿及维护流程

### 3.1 字段约定

| 字段 | 新增/编辑初值 | 保存规则 |
| --- | --- | --- |
| wearDate | 空日期入口传选日；搭配入口为2026-11-06；编辑原日期 | 必填真实YYYY-MM-DD，不能晚于演示基准日，且与其他工作日记日期不冲突 |
| sourceOutfitId | 直接补记null；搭配入口用来源ID；编辑沿用 | null或当前工作搭配ID，允许归档；表单只读说明，不设无需求的换来源功能 |
| clothingIds | 直接补记空数组；搭配入口复制完整顺序；编辑复制当前日记清单 | 1～20个有效工作衣物字符串ID、无重复，数组顺序就是实际展示顺序 |
| occasion | 直接补记空；搭配入口复制场景；编辑原值 | trim后1～20字符；可用现有场景快捷项，也可输入新场景 |
| mood | 表单新增空字符串；编辑原心情或空字符串 | 选填；保存时空白归一为null，非空trim后1～12字符；轻松/专注/愉快/从容/放松/平静/满意快捷项不限制自定义 |
| note | 新增空字符串；编辑原文字 | 0～1000字符，保留换行，不trim掉有意义内容 |
| photoPath | 新增null；编辑原路径或对象URL | 选填；移除明确为null；新本地图在选择入口通过校验后才能使用 |

新增提交由程序生成id、userId=DEMO001、origin=prototype，不加入isArchived（日记无归档需求）。编辑保留id/userId/origin，仅更新上述完整表单字段。原型沿用CLO/OUT/DIA及TMP字符串ID，不能套用数据库正整数ID校验。

工作数据mood=null与表单空字符串是同一个合法空值的不同表示；建立草稿及初始快照时一并映射，避免Array.from(null)报错或未修改就被判为脏表单。photoPath和sourceOutfitId在草稿中仍可为null。现有通用输入计数按name/其他/备注硬编码，复用时必须改为当前实体字段上限：日记场景20、心情12、文字1000，不能沿用搭配备注500。

字符串按Array.from的字符数量计数，显示长度提示；不靠maxlength截断超长输入。输入只改变草稿，保存入口校验一次完整表单；错误按字段提示并定位首错，工作记录、ID计数和统计均不改变。输出延续现有文字转义，备注与名称不作为HTML执行。

### 3.2 新建、编辑与取消

1. 进入表单时创建独立草稿和初始快照。搭配衣物数组、编辑目标日记数组及选择器数组不得共享可变引用。
2. 选择衣物复用现有面板：默认在用、可包含归档；完整已选区保留不在当前筛选中的项。清除筛选不清已选、保留归档开关；重新勾选追加到末尾。
3. 选择器确定只更新父草稿，0件也可回表单但不能保存；取消、Escape、遮罩丢弃面板改动，不再叠加放弃确认。最多20件，第21件明确反馈；移除后可再选。
4. 主表单已选区展示全部单品，首项上移/末项下移禁用，移除只改草稿；排序后保持目标行可见与操作焦点。
5. 保存通过全部校验再一次写工作记录，衣物数组复制；重建索引、刷新关联、定位成功详情，提示“已保存到本次演示”。校验失败保留全部输入及照片。
6. 返回/取消经过统一退出入口。未改直接返回；改过并改回初值视为未改；有改动确认放弃，拒绝后保留草稿、照片和位置。
7. 有脏草稿才注册beforeunload；成功保存或放弃后解除。刷新确认才重置，取消浏览器离开不清草稿、不提前撤销图片。

从搭配预填后调整衣物、场景或排序，sourceOutfitId继续保留，并说明“由××搭配发起，实际单品以本篇记录为准”。不显示“与来源实时同步”，不提供自动同步按钮。后来修改来源名称时链接显示当前名称，修改来源清单时旧日记清单保持；衣物当前名称/图片改变可反映在日记，这是无属性历史版本的既定规则。

### 3.3 删除

仅P08有删除入口，提示“删除2026-xx-xx的穿搭记录？仅本次演示生效”。取消立即停留，不改变工作数据；确认后从data.diaries移除该ID，不删除衣物、来源搭配、原素材或磁盘图片。完成第2.3节的日历定位、重算及自有URL引用清理。没有回收站、撤销队列或批量删除。

## 4. 日期、未来日期与同日冲突

### 4.1 固定演示时间

在日历、日记表单和统计中清楚显示“演示基准日：2026-11-06”。“演示今天”定位该日；新增默认、未来判断、累计截至日期和30天窗口共用该值，不混用浏览器new Date当天。初次浏览仍选11月5日，以保留P1-01/P1-02基线。

未来真实小程序改由服务端按Asia/Shanghai当天提供权威日期，本原型固定日期不是公共API允许任意asOf的设计，也不自动平移旧样例。展示月份可前后浏览，包括未来月；未来日期只显示“未来日期暂不能记录”，不提供新增入口。

日期用原生date控件，显示YYYY-MM-DD语义并设最大演示日；保存时仍对草稿校验格式和真实公历日期，不能仅靠max属性。计算日期窗口用统一自然日运算和年月日回读核对，避免Date把2月30日滚到3月；不以浏览器本地时区/夏令时影响日界。原生控件拒绝无效日期变空时应给有效日期提示；测试侧可临时改输入类型传非法文本检验保存入口，不给产品加测试入口。

### 4.2 唯一与冲突交互

保存前在data.diaries查找相同userId、wearDate且id不同于编辑目标的记录；编辑原日期不算冲突。校验失败或日期冲突不消耗TMP-DIA编号，不清文字、图片和已选顺序，也不覆盖已有记录。

冲突提示放在日期附近：“该日期已有穿搭记录”，提供“查看已有记录”和“编辑已有记录”。点击前仍不改工作数据。若当前草稿有修改，确认“放弃当前未保存内容并打开已有记录？”；拒绝留在当前表单；确认后释放未提交资源，撤去当前表单帧，打开冲突ID详情（编辑入口再进入其新编辑草稿）。不在背后保留另一份未保存草稿。

冲突导航保留原表单之前的来源帧；若其紧邻帧已是同一日记详情，复用该帧，不重复压栈。由该详情再返回不会进入已放弃的旧表单。查看冲突记录不直接改日历选日，只有成功保存或删除按第2.3节定位。

示例：初始11月5日已有DIA012，直接补记入口应引导查看或编辑，不提供第二篇；从搭配发起后把日期改到11月5日，保存显示冲突。编辑DIA012保持11月5日可保存，改到已有11月3日冲突，改到空白10月8日则移除11月5日标记并新增10月8日标记。

## 5. 可选照片、对象URL与内存组织

### 5.1 选择与展示

新增无照片合法，使用当次衣物展示。编辑未重新选图沿用原photoPath；选图取消不改变旧图。接受JPEG/PNG、最大5MiB，浏览器成功解码才替换草稿；错误类型、超限、损坏文件显示原因并保留此前有效图。新图解码中禁用本次选图控件和保存，允许取消表单，不显示服务器上传进度。

移除照片仅令草稿photoPath=null；此时若取消编辑，原工作照片必须还在。保存移除才改工作记录并清理不再被引用的自有URL。无照片与图片读取失败分开：前者正常展示衣物，后者保留照片位置/说明并提示失败。

### 5.2 必须改动的引用清理

复用ownedUrls，但把cleanUrls的“正在使用”集合扩大为：

- 全部工作衣物的imagePath（包括已归档）。
- 全部工作日记的非空photoPath。
- 当前活动草稿的imagePath和photoPath。
- 当前仍在解码的待选对象URL。

仅撤销ownedUrls内且已无上述引用的地址；assets相对路径或其他源图片不在自有集合中，绝不revoke。无需另建引用计数表，当前数据规模遍历即可。

| 时机 | 清理要求 |
| --- | --- |
| 替换草稿照片 | 新图解码成功后再替换并清理上一张仅属草稿的临时图；工作记录旧图继续有效 |
| 无效新图 | 撤销本次无效URL，保留旧有效图；不改变衣物图片 |
| 移除草稿照片 | 草稿取消时仍应能恢复原工作图；只有无其他引用的草稿临时图可立即清理 |
| 取消表单/确认放弃冲突草稿 | 撤销草稿独有的图；原工作衣物、其他日记及当前编辑记录旧照片均保留 |
| 保存新图或新日记 | URL转由工作日记持有，不能因为表单关闭而释放 |
| 保存替换/移除或删除日记 | 先刷新相关可见视图，再撤销已无工作记录/草稿引用的旧自有地址 |
| 切tab、看图关闭、归档/恢复 | 工作记录仍持有图片，不释放 |
| 刷新/关闭尝试 | beforeunload不释放；真正离开由浏览器销毁页面资源 |

图片解码闭包持有发起草稿和目标字段。用户在解码结束前离开时，结果不再写入新页面或新草稿，完成后撤销无主URL；预期decode失败小范围捕获，不能包整个保存流程吞异常。跨衣物/日记复用选图时显式传目标字段，不把日记照片写进imagePath。

不新增导出图片、图片持久缓存、base64存储、自动文件清理或网络上传。各记录本身持有照片路径，详情帧不额外持有旧图副本。
