## 3. C01～C08契约与实现约定

### 3.1 通用规则

接口前缀统一`/api`，全部要求现有Bearer认证。未知身份先401；资源不存在或属于他人统一404 `NOT_FOUND`；输入无效400 `INVALID_INPUT`，图片引用不合法400 `INVALID_IMAGE_REF`。成功JSON沿用`{data:...}`，错误沿用现有标准格式，不暴露SQL、磁盘绝对路径、密码或令牌。

HTTP入口一次完成字段白名单、类型、长度、枚举及规范化，内部服务使用规范化结果；图片引用跨文件系统边界使用已有校验。所有查询及写入绑定当前用户，客户端不提供userId。C05/C06先确认当前用户目标存在，再做图片引用或写入，避免访问他人资源时产生副作用。

| 项目 | 明确规则 |
| --- | --- |
| ID | 路径十进制正整数，1～4294967295；不接受小数、指数、数组或对象 |
| 分页 | query十进制整数字符串；缺省page=1、pageSize=12，page>=1，pageSize=1～50；offset必须是安全整数；空串不等于缺省 |
| query | 拒绝未知字段、重复参数形成的数组/对象；不使用通用类型强制转换接受非法值 |
| 排序 | 衣物/相关搭配id降序，历史wearDate降序、id降序；明细sort_order升序；无客户端自由排序表达式 |
| 归档 | active默认、archived、all；归档详情仍可读、可编辑、可恢复 |
| 返回类型 | id和数量为JSON数字、isArchived为boolean；无最近日期为null；无备注为空字符串 |
| 时间 | 显式写UTC DATETIME(3)，不修改表默认值；响应createdAt/updatedAt为带毫秒与Z的ISO UTC；自然日仍YYYY-MM-DD |

### 3.2 接口逐项安排

| ID / 请求 | 输入及成功结果 | 核心实现与验证 |
| --- | --- | --- |
| C01 GET `/api/clothes` | keyword/categoryId/color/season/archived/page/pageSize可选；200分页ClothingSummary | AND组合，当前用户范围，id倒序；页外返回items=[]并保留total |
| C02 GET `/api/clothes/facets` | 仅archived可选；200 `{colors:[...]}` | 当前用户+该归档范围的DISTINCT完整颜色，按既定排序规则文字排序；不受其他筛选影响；先于/:id注册 |
| C03 GET `/api/clothes/:id` | 无query；200 ClothingDetail | 自有衣物含归档；关联日记独立聚合wearCount/lastWornDate，无记录为0/null |
| C04 POST `/api/clothes` | 完整衣物表单；201 ClothingDetail | 服务端生成ID、用户归属、未归档状态及时间；名称允许重复；使用真实insertId |
| C05 PUT `/api/clothes/:id` | 同C04完整表单；200 ClothingDetail | 不允许修改userId、归档或创建时间；同值提交也成功，不能把changedRows=0当不存在 |
| C06 PATCH `/api/clothes/:id/archive` | 仅`{isArchived:boolean}`；200 ClothingDetail | 只改标记和必要更新时间；重复设置当前标记成功且不人为改变更新时间；不动关联和图片 |
| C07 GET `/api/clothes/:id/outfits` | 仅page/pageSize；200分页OutfitSummary | 先核对自有衣物；含归档搭配并标记；完整数量、前4件有序预览 |
| C08 GET `/api/clothes/:id/diaries` | 仅page/pageSize；200分页DiarySummary | 先核对自有衣物；通过diary_items找实际穿着；完整数量、前3件有序预览 |

ClothingSummary精确沿用`id/name/categoryId/color/season/imagePath/imageUrl/isArchived`；ClothingDetail再加`note/createdAt/updatedAt/wearCount/lastWornDate`。不附带密码、userId、SQL列名或额外计数字段。

OutfitSummary沿用`id/name/occasion/isArchived/clothingCount/previewItems`。DiarySummary沿用`id/wearDate/occasion/mood/clothingCount/photoUrl/previewItems`，mood和photoUrl可null。**不为阶段4擅自增加photoPath字段。** P02历史区显示衣物预览、日期/场景/心情及可选“有照片”提示，完整日记照片留日记详情，不将photoUrl直接作为image源或冒充稳定路径传给media。

### 3.3 筛选及表单校验

keyword trim后0～40个Unicode码点，空串表示不筛名称；大小写不敏感的字面子串匹配。categoryId必须为现有7个字符串分类之一；color trim后1～20，按完整文字精确匹配，不猜测色系。前端“全部”通过不传对应参数表达，不传伪枚举。

季节查询只接受单季，服务端映射如下；表单保存支持8个原始值，不能混淆查询与保存枚举。

| 查询 | 匹配存储值 |
| --- | --- |
| 春 | 春、春夏、春秋、四季 |
| 夏 | 夏、春夏、四季 |
| 秋 | 秋、春秋、秋冬、四季 |
| 冬 | 冬、秋冬、四季 |

C04/C05只接受且必须提交`name/categoryId/imagePath/color/season/note`：name trim后1～40、color trim后1～20、单行；分类7选1；season为春/夏/秋/冬/春夏/春秋/秋冬/四季；imagePath为1～255的当前用户有效稳定图片路径且不能null；note为0～500字符串，保留换行，空备注显式`""`，不以null或缺失补旧值。

Unicode长度用与现有昵称相同的码点计数思路，前端原生maxlength不靠UTF-16截断形成不一致；字段长度提示与服务端一致。非法字段定位到可修改控件，保留草稿；服务端校验为权威。名称重复是合法业务，不新增唯一约束或重复名称错误。

### 3.4 SQL、统计与事务

- 所有文本值参数绑定。keyword先把`!`转`!!`、`%`转`!%`、`_`转`!_`，使用固定`LOWER(name) LIKE ? ESCAPE '!'`；反斜杠是普通字符，不依赖会话反斜杠转义模式。验证特殊字符不会变成通配或SQL片段。[MySQL 8.0 LIKE说明](https://dev.mysql.com/doc/refman/8.0/en/string-comparison-functions.html)
- LIMIT/OFFSET只可由入口已校验的安全整数生成数字字面量，不拼接任何原始query、列名或排序；其余值使用execute绑定。mysql2文档说明数字绑定类型为DOUBLE，选用此有限数值拼接方式，避免把未实测的LIMIT绑定兼容性写成事实。[mysql2预处理说明](https://sidorares.github.io/node-mysql2/docs/documentation/prepared-statements)
- C01/C07/C08各自使用同一连接只读事务完成total、主列表及必要预览，保证单次响应快照一致；不跨HTTP持有事务。主列表先分页，再批量读取该页父ID的明细并分组截取预览。不要用目标衣物条件截断预览，也不要对每行单独再查完整详情。
- C03统计从当前用户diaries与diary_items计算，请求开始取Asia/Shanghai当天；只计wear_date不晚于当天的关联日记，COUNT为篇数，MAX为最近日期。归档衣物仍有穿着历史。无日记为0/null，不能用外连接COUNT(*)得到1；不要把搭配关联一起连接导致日记重复计数。[MySQL聚合函数说明](https://dev.mysql.com/doc/refman/8.0/en/aggregate-functions.html)
- 统计不维护衣物计数字段、不使用demo-summary作为运行答案，不接受公共asOf调试参数。内部可注入日期用于确定性测试，真实HTTP始终使用服务器当天。
- mysql2现有DATE/DATETIME字符串配置保持；UTC DATETIME转ISO时显式按UTC解释，不用本机时区解析无时区SQL字符串；展示可格式化本地时间，不能回写改变原值。
- C04～C06为单行原子写入，无跨表组合事务，不引入通用事务框架。C05更新后重新读取派生详情；未知异常交全局错误处理，不大量try/catch吞错。
- C07/C08中父记录与预览衣物均限制当前用户，关联存在性判断与预览集合分开；源搭配只表示来历，不能用outfit_items替代diary_items。发现现存跨用户异常关系先停止夹具写入并定位，不为了测试制造非法归属数据。

### 4.2 P01列表与筛选

首屏依次为标题/新增、名称搜索、归档范围、分类、更多筛选入口/已选条件、结果总量、两列单品、加载更多/末尾提示。页面自然纵向滚动，底部tab与安全区保留；不能把整页再套无必要滚动容器。

- 搜索分keywordDraft与已应用keyword，点搜索或键盘确认才请求；清空搜索只清keyword，不连带其他筛选。分类和归档切换立即应用。
- 更多筛选使用当前页内面板，草稿color/season点“应用”才提交，取消不改变已应用条件；面板“重置”只清该面板草稿。主页面“清除筛选”清名称/分类/颜色/季节，保留用户选择的归档范围。
- 分类由A06，颜色由C02，季节固定四单季；C02只随归档范围或成功维护后更新，不随名称/分类变化收窄。所选颜色不在新facets中时仍保留可清除的选中条件，允许返回无结果，不静默换色。
- 所有筛选AND；应用任何条件重置page=1与滚动到顶部。默认12条；触底与“加载更多”共用加载锁，成功后才推进页码和追加；失败保留已有列表，手动重试同一页。总量已展示完显示“已全部显示”。
- 真正无衣物显示新增入口；有筛选但无匹配显示清除筛选；加载中、首屏加载失败、下一页失败、图片失败分别处理，不用假数据补结果。A06/C02失败提供各自重试，不清空已应用条件。
- 未写入时，切tab及详情返回保留筛选、已加载数据和滚动位置；成功新增/编辑/归档使该账号衣橱失效，返回按保留筛选重查第一页、滚到顶部。新衣物不满足当前条件时提示已保存但不强行改筛选，末页最后一项归档后同样回到有效第一页。

### 4.3 P02详情与关联区域

顺序为完整单品图、名称/归档标记、分类颜色季节、备注、穿着次数/最近日期、相关搭配、穿着历史、编辑/归档或恢复操作。归档标记独立，不挤占长名称。

C03为主区域；C07/C08各自加载、空态、失败重试和分页，不因一个历史区域失败隐藏主详情或另一区域。主详情404显示“衣物不存在或无法访问”和返回衣橱；其他错误保留明确重试。

两个历史区域前端各用pageSize=2，以少量记录验证2+1分页，接口默认仍12；分别保留自己的页码，其他区域加载不清空它。搭配显示完整数量及前4件、归档标记；日记显示日期、场景、心情、完整数量及前3件，缺心情省略、无照片不显示坏图。未开放详情的说明见第2节。

归档和恢复均先原生确认，操作中禁重复提交；取消不写接口，失败保持原状态。归档后仍能查看、编辑和读取关联，恢复后回到默认衣橱。不存在物理删除入口。

### 4.4 P03表单与图片

字段顺序：必填单品图片、名称、分类、颜色、适用季节、可选备注、保存/取消。新增不擅自预选分类和季节，显示“请选择”；分类加载失败可重试，不能绕过有效分类保存。编辑完整预填，包括归档衣物。

复用P3-03选择与media能力：本地选择→本地预览→A07上传取得稳定imagePath→C04/C05保存。区分已保存路径、最近成功上传的草稿路径和当前候选本地路径；上传中禁保存，失败可重试或放弃候选恢复前一成功草稿。只在C04/C05成功后更新衣物已保存状态，选择取消不视为改图。

图片JPEG/PNG、最大5MiB及服务端可解码规则不变，不重复实现解码；C04/C05复用已有image-reference路径、归属、普通文件和签名校验。A08下载成功得到的临时路径只用于显示，wx临时路径/blob/imageUrl不能写入clothes.image_path。

保存失败保留表单和已上传稳定路径，手动再保存不重复上传；上传成功后取消、换图或归档均不删除成功文件，新增文件清单记录未引用状态。请求超时可能已写入时说明“保存结果未确认，请先查看衣橱”，不声称一定未写入、不自动重发或新增幂等表；名称允许重复，用户检查后再决定。

dirty比较规范化字段与原值，并包含待处理图片候选；页面取消和现有原生alertBeforeUnload协调成一次未保存提示。确认放弃才离开，继续编辑保留草稿，保存中防重复点击。原生手势返回/退出小程序不具备完整拦截保障，此限制如实记录，不能用页面取消弹窗冒充所有原生返回已验证。

### 4.5 会话、迟到响应及视觉
