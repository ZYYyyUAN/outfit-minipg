## 3. 接口与事务实施约定

### 3.1 O01～O06

所有接口前缀/api，除既有匿名接口外都认证；当前用户仅来自认证上下文。成功套data，创建201，其余200，错误沿用标准JSON。路由顺序为认证→该路径8KiB JSON解析→入口校验→服务。未登录的损坏/超限JSON仍先401。facets固定路由先于/:id；不更改全局未实现接口404行为。

| 编号 | 请求与校验 | 成功结果及语义 |
| --- | --- | --- |
| O01 GET /api/outfits | keyword可省略或0～40字符；occasion传入时1～20字符；archived为active/archived/all默认active；page默认1，pageSize默认12、1～50 | items/page/pageSize/total；id降序；keyword忽略大小写的字面子串，转义!、%、_并绑定参数；场景完整文字精确匹配；条件AND |
| O02 GET /api/outfits/facets | 仅archived，默认active | data.occasions为当前用户该范围去重场景，按数据库既定文字排序；不随keyword或occasion收窄 |
| O03 GET /api/outfits/:id | 十进制正整数1～4294967295，无额外query | OutfitDetail，归档仍可读；不属于本人/不存在同404 |
| O04 POST /api/outfits | 完整name、occasion、note、clothingIds，不接受额外字段 | OutfitDetail、201；实际insertId，服务端写user_id、UTC时间、未归档 |
| O05 PUT /api/outfits/:id | ID和完整表单，字段不缺省 | 更新后OutfitDetail；保留user_id/created_at/is_archived，不修改日记 |
| O06 PATCH /api/outfits/:id/archive | 仅isArchived真实boolean | OutfitDetail；重复相同目标成功且不改updated_at；归档不删明细或日记来源 |

参数不能静默把空值当未传；拒绝重复/对象query、未知字段、非法ID、分页及不安全offset。name/occasion按Unicode码点计1～40/1～20，trim后不能换行；note保留换行，0～500，空串明确提交。名称可重复。clothingIds必须为1～20个JSON整数、范围1～4294967295、无重复、有序；空/重复/超限/无效选择统一INVALID_SELECTION；格式字段错误INVALID_INPUT，字段提示只含本人可操作内容。

OutfitSummary字段固定：id、name、occasion、isArchived、clothingCount、previewItems（前4个ClothingSummary）。不足4件只显示实际数量，不补假图；总件数不是预览件数。OutfitDetail字段：id、name、occasion、note、isArchived、items（全部有序ClothingSummary）、createdAt、updatedAt。子项来自衣物当前属性，归档独立标记；ISO时间含毫秒和Z，数字/boolean不返回SQL字符串/0/1。imagePath稳定，imageUrl派生，显示通过media下载，不把鉴权URL直接给image组件。

列表在同一只读快照中查total、当前页及子项；批量查询该页搭配的所有明细并分组，按sort_order取前4，不逐行查询，不因过滤目标衣物截断其他成员。详情按完整清单有序读取。父查询及子项JOIN均限定当前用户，避免他人衣物信息泄露。SQL LIMIT/OFFSET只使用已校验安全整数；其他用户输入绑定，不拼SQL排序表达式。

### 3.2 写入与失败原子性

请求格式只在外部入口校验一次；服务层负责查询用户归属和存在性，不重复校验长度类型。O05/O06先确认父记录归属，失败404，不通过后续所选衣物错误泄露他人搭配存在性。O04/O05一次IN查询全部所选衣物并校验均属当前用户；归档衣物是允许选项，不当作不存在。错误不返回别人ID对应的名称等信息。

O04在同一连接事务内校验选择、插入outfits、按数组顺序插入outfit_items（sort_order=1～n）、读取响应并提交。O05在同一连接事务内读本人父记录、校验选择、更新主表、删除仅该搭配旧明细、插入新明细、形成响应、提交。为避免同一父记录的编辑和归档交错，写入事务以本人父行的锁定读取串行该次写操作；这是本阶段事务一致性的限定范围，不增加版本字段、重试或锁框架。O06同样在事务中读/更新本人父行，重复目标不更新时间。

只有提交成功才返回成功；错误时回滚并释放连接，未知错误交全局500，不吞掉或伪装成成功。事务try/catch仅承担rollback并重新抛出，finally释放；不将整个业务包成返回null。没有跨文件事务、自动重试或二次请求补救。保存失败保留完整草稿，用户手动重试。

O04/O05/O06不得写diaries/diary_items，不维护穿着次数。日记来源只表示来历，实际衣物集合和顺序不随搭配变化；搭配/衣物当前名称与图片不建立历史版本。保存搭配前后核对C03的wearCount/lastWornDate、日记行及明细不变，完整统计HTTP等阶段6。

## 4. 原生页面、导航与状态

### 4.1 页面组织

沿用实际原生路由风格：P04为已有`pages/outfits/index`；P05拟`pages/outfits/detail/index`；P06拟`pages/outfits/edit/index`。详情/编辑在app.json注册，新增编辑同页由是否有id区分。新增页面使用四件套js/json/wxml/wxss；tab不更名，不能照抄HTML。

P04首屏标题/新增、名称搜索确认、场景/归档筛选、数量、两列真实2×2组合预览；每卡name最多两行、场景、总件数和独立归档文字。默认active，每页12，触底/更多逐页；筛选改变清空旧页回第1页。输入keyword在确认前不触发搜索，面板条件在应用前不改列表，取消不改；重置清keyword/occasion回active，清除无结果条件行为同样明确。区分无搭配、筛选无结果、首屏失败和追加失败，后者保留旧页并重试原页，不自动推进page或重复追加。

P05展示名称、场景、备注（空时暂无备注）、归档标记、全部有序衣物（最多20件、完整图片、名称和当前归档标记）、编辑、归档/恢复、记录穿着入口；每件点开P02，图片失败单独重试。不能把前4张当详情全集。归档前确认，取消不请求；恢复成功有反馈。O03的404显示统一不存在/无法访问和返回，不假称另一个账号确有该记录。

P06展示名称、场景、备注计数、选择衣物入口、全部已选有序列表、移除/上移/下移、保存/取消。新建初始空；编辑仅由O03完整items初始化，不能由卡片预览预填。归档搭配仍可编辑但不暗中恢复。保存前展示字段错误并滚动到首项；空清单不能保存；保存中阻止重复点击与改草稿，失败保持所有输入和顺序，可手动重试。note保留换行，单行名称/场景不能换行，服务端错误映射字段，不丢已选数据。

### 4.2 返回、刷新与跨模块联动

P04→P05→P02用navigateTo，系统返回逐层navigateBack；P02来自衣橱或搭配必须回原调用页，不固定switchTab衣橱。可先用页面栈判断有前页则返回，无前页才回对应tab，不引入通用路由器。P02原“返回衣橱”错误入口按真实来源处理。P02相关搭配摘要接通P05，独立分页和图片重试按钮不误触导航；穿着日记详情继续明确未开放。

新增保存：以redirectTo将编辑页替换成新P05，使返回到P04而不是重新进空表单。从P05编辑保存后navigateBack回同一P05重新查；页面栈异常的直接进入场景回该搭配详情。取消原样返回，不生成数据；页面取消必须提供未保存确认，原生返回是否可拦截以工具实际能力核对，不写成通用保证。若当前可用API不能可靠拦截，页面明显提供取消入口并记录原生返回限制，不伪造原生拦截已验收。

P04无写入返回保留已应用条件、分页和滚动；P05进入P02后无写入返回保留详情位置。搭配写入成功使搭配列表/详情重新查询，场景facets随归档范围更新；P02相关搭配摘要需要失效刷新。衣物改名/换图/归档后，搭配列表预览、详情和选择器下次显示重查当前属性，不缓存旧图片地址。复用wardrobe revision并增加仅会话内的outfit revision，数据读与版本号按session epoch隔离；没有写入不无故重置滚动。需要刷新时回第1页并明确恢复顶部，不把新页和旧页混拼。P02的穿着统计不因仅保存搭配增加。

页面离开/卸载后及账号变化，所有请求、图片下载、选择器和保存回调检查会话epoch与页面查询序号；旧成功不刷新新账号、不跳新页面、不展示旧图片。onShow守卫、onHide清显示/失效回调模式复用现有实现，不另建令牌逻辑。必要时从详情返回已隐藏的编辑草稿，草稿仅保留当前会话，不进storage；不同账号永不共享。

## 5. 衣物选择面板与草稿

原生目前无选择器，需要本阶段新增一个可供日记复用的组件，拟`miniprogram/components/clothes-picker/index`四件套。它只管理面板内选择草稿和展示，不写搭配；父表单传已选有序衣物、会话版本，确认发出完整选择，取消/关闭/遮罩不改父草稿。只有实际复用需要才独立组件，不建组件库或通用状态容器。

查询复用A06/C01/C02：keyword确认、分类、颜色、单季、归档范围（默认active，可切archived/all）及12条分页；归档带标记且允许选择。查询变化清当前结果/分页，但保留panelSelected有序ID数组及selectedById当前详情；换筛选、翻页不会清空选中。打开时复制父数组和对象，不能共享可变引用；编辑中已有归档项即使默认列表看不到仍列在已选区。再次打开按父最新草稿初始化，不沿用此前已取消的面板状态。

去重以真实整数ID，按首次选入顺序追加，反选从清单移除；最多20件，达到上限只阻止新增，仍可反选。已选区可移除、上移、下移；首尾相应按钮禁用（不循环），父表单也可调整。确认0件允许回父表单，但父表单保存必须报至少1件；确认仅改草稿，不发O04/O05。必要时读取C03更新已选属性，不每次全量查询全部衣橱、不拉全量JSON；来自O03的完整items可作为初始显示。

选择器header关闭、底部数量/确定固定，中间结果与已选列表可滚动，面板底部安全区留白；连续20件、长名称、图片失败、无匹配和请求失败都有可操作反馈。面板打开时遮住底层操作，关闭返回原触发位置；取消与确认事件不可同时触发。涉及未保存离开时比较规范化字段及有序ID数组，不把仅打开取消或筛选视为业务修改。

## 6. P5-03入口交接

阶段5不新增D接口或日记页。P05“记录穿着”先校验当前详情已加载且会话有效，用当前真实id构造`{sourceOutfitId: id}`入口描述（可用独立小工具，供阶段6替换处理）；当前点击以明确说明反馈“日记录入将在下一阶段接通，当前搭配尚未生成穿着记录”，显示来源搭配名称/ID便于核验。按钮不是静默无效，也不导航未注册页面、不显示保存成功。
