```powershell
Set-Location -LiteralPath 'Z:\outfit\personal-wardrobe\server'
npm start
```

保留server/.env与uploads。配置键见[.env.example](../server/.env.example)：PORT、PUBLIC_BASE_URL、DB_HOST、DB_PORT、DB_NAME、DB_USER、DB_PASSWORD、UPLOAD_ROOT；密码本机填写，进程环境优先。库固定wardrobe_demo、主机127.0.0.1、UPLOAD_ROOT=./uploads相对server。默认3000，PUBLIC_BASE_URL=http://127.0.0.1:3000，客户端[config.js](../miniprogram/config.js)为http://127.0.0.1:3000/api。

启动先认证并核对7表再监听。http://127.0.0.1:3000/api/health仅证明HTTP响应，登录读衣橱才证明认证业务链，均不能替代原生编译/交互验收。本轮自有3017已关闭，原3000进程未动，不承诺永久存活。占用时先识别，不停止未知进程；改端口需同步PORT、PUBLIC_BASE_URL和客户端配置。

**现有库禁止schema/种子重导、清表或重置ID。** demo_user密码保持原值。新用户无24/8/12样例；本轮账号凭据仅本机server/.p7-private/delivery.json，已退出，不入包。

## 小程序与演示

导入miniprogram目录，复制[project.config.example.json](../miniprogram/project.config.example.json)为本机project.config.json并填自身可用AppID，真实配置不入包。开发者工具服务端口保持关闭。历史工具2.02.2609250/基础库3.18.0，本轮未重新编译或人工验收。

答辩自行操作（不是本轮人工记录）：

1. 登录，衣橱筛选、详情；新账号先上传并建衣物。
2. 选衣保存搭配，查看完整顺序，进入单品逐层返回。
3. 从搭配记录今天或过去空日，日历查看独立日记清单。
4. 看统计，修改来源搭配，打开旧日记确认独立。
5. 改记/删记看统计回退，归档恢复，最终退出。

同日仅一篇，日期按服务器上海当天；30天窗口随当天变化。所有图片鉴权读取，成功上传未引用文件保留。草稿不保证退出后保留，原生键盘/手势返回/尺寸未验。prototype是历史静态设计。关闭本人前台后端用Ctrl+C等待closed，不关闭MySQL/未知Node；未交付后台自启。

## 新机器首次准备（未执行净机复现）

仅用于**确认的新建专用空库**，禁止用于现有库。需Node24.x、npm、支持ENFORCED CHECK的MySQL8.0、开发者工具及可用身份。

1. server和database各运行`npm ci --no-audit --no-fund`，需网络及Sharp可选平台包。本轮未净机验证。
2. 本机MySQL客户端安全交互输入凭据，执行[schema.sql](../database/schema.sql)。这是建库建表写入，确认无旧业务，禁止覆盖。
3. 准备server/uploads/users及server/.env；数据库工具从进程环境读DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD，示例不是可用凭据。
4. 项目根运行`pwsh -NoProfile -File .\database\run-demo-local.ps1`导入固定样例。这是写操作，包含空库预检、回滚验证和一次正式导入，安全提示输入数据库及演示密码。保留新runId和映射，见[P2-03](P2-03执行与验收记录.md)。不导入样例也须按schema/设计初始化7分类才可建衣物。
5. 原data/assets映射为24衣物/8搭配/12日记，整数ID实际生成，固定历史日期不保证最近统计固定；再按前节启动配置。

包不含当前数据库/凭据/uploads/实际AppID。素材限制见[来源](../assets/SOURCES.md)，品牌图为实训参考，未获单独再分发授权。包称源码及恢复材料，不宣称解压即用。
