## 后端配置与启动

本机Node为24.16.0，npm 11.14.1。后端使用独立server包，Express 5.3.0、mysql2 3.24.6、Multer 2.5.0、Sharp 0.35.5及package-lock固定依赖。npm ci已在本机Windows x64成功验证，需保留Sharp平台可选依赖。数据库结构及导入工具不重跑。

在PowerShell中运行：

```powershell
Set-Location -LiteralPath 'Z:\outfit\personal-wardrobe\server'
npm ci --no-audit --no-fund
npm start
```

启动前准备server/.env（本机已通过隐藏输入准备，Git忽略）或完整进程环境。键见.env.example：PORT、PUBLIC_BASE_URL、DB_HOST、DB_PORT、DB_NAME、DB_USER、DB_PASSWORD、UPLOAD_ROOT。进程环境优先；PORT默认3000，其余必填。示例没有可用数据库凭据，应在本机填写或通过隐藏输入注入，不能将密码粘贴到聊天/命令参数。

当前origin为http://127.0.0.1:3000，健康地址为http://127.0.0.1:3000/api/health。启动先只读确认MySQL目标与7表再监听，分别输出database-connected和http-listening。health只表示HTTP进程可响应，返回`{"data":{"status":"ok"}}`，不返回数据库或账号详情。

UPLOAD_ROOT的./uploads相对server目录解析，本机为Z:\outfit\personal-wardrobe\server\uploads。正式用户目录users/11与回滚遗留目录users/10各25张，不移动、覆盖或清理。不公开静态/uploads路径；A08按当前用户目录鉴权读取。新上传文件以本轮manifest登记，不覆盖或删除这50张图。

端口占用时程序报告EADDRINUSE并关闭本轮连接池，不自动改端口或停止占用者。先检查实际进程，确定新端口后同步PORT、PUBLIC_BASE_URL和miniprogram/config.js。数据库库名固定wardrobe_demo；不得因连接失败建替代库、清表或重新导入。

## 小程序导入与页面

导入根为Z:\outfit\personal-wardrobe\miniprogram，不是整个仓库。复制project.config.example.json为本机project.config.json，配置本项目实际可用AppID或工具明确支持的本地模式。实际项目配置与project.private.config.json均忽略，不提交账号信息或本机工具设置。

首开为登录页；注册成功返回登录并只预填用户名，不自动登录。登录后四个tab依次为衣橱、搭配、日记、我的，前三页仍明确功能待开发。我的展示真实账号和昵称，可进入资料页保存昵称或退出；健康按钮仍匿名。小程序config.js中的apiBaseUrl为http://127.0.0.1:3000/api，request只接收/me、/auth/login等相对路径，不能重复/api。

在本项目开发者工具里确认基础库、项目编译及本地网络访问设置。实际身份/工具条件和截图以P3-01执行记录为准，不能用其他项目或浏览器预览代替。

本机实际工具为2.02.2609250 Stable，基础库3.18.0，本项目AppID由用户在本机导入配置。新版不接受旧touristappid占位值，其他机器应配置自身可用身份；不要直接把模板占位值当成可编译配置。工具服务端口按用户要求保持关闭，UI验收由用户手动执行，脚本不要求开启它。

## 测试、只读复查和关闭

```powershell
Set-Location -LiteralPath 'Z:\outfit\personal-wardrobe\server'
npm test
npm run verify:media -- --audit run-20261108-01
```

test运行119项配置/HTTP基础回归、认证、完整图像解码/边界、隔离IO故障与客户端回调检查；临时文件测试只操作自己创建的临时根，其中启动失败/端口占用组需要当前本机数据库私有配置，不写数据库。

verify:media -- --audit <既有批次>只读检查目标库/文件，写本阶段证据和manifest。原有文件逐字节不变，新增集合必须恰好等于登记清单；本轮预留人工账号及提供的UI素材可以从实际SQL归属、文件SHA独立登记。测试账号须最终退出，未解释的新账号/文件会失败，不能靠删除它们通过。

完整HTTP验收命令为 `npm run verify:media -- --run-id <唯一新批次>`，属于**真实写入**，会注册两个专用账号、上传若干文件、修改专用资料并最终退出，账号及成功文件保留；不用于随手检查服务，不覆盖旧批次。脚本用仅自己拥有的短生命周期独立应用进程进行真实重启，私有环境只继承到进程，不放argv。Windows终止方式如为强制结束不宣称优雅关闭；不停止MySQL或其他node。人工演示仍用3000端口的前台npm start。

旧verify:auth/verify:foundation的完整main、固定用户/原50图集合及旧源码指纹已不适用，不再执行，也不写P3-02旧报告；不运行种子导入或空表约束模式。新批次用户数、上传文件数按实际登记，不删账号/清目录或重置自增。

客户端只在本项目登录storage键保存token和expiresAt，启动通过A04恢复资料。7天固定期限、不续期；同一账号新登录取代旧token。退出须服务端确认；网络失败不会假退出。实际密码、token及摘要不进入文档或Git。

头像现可选择本地图、完整上传并保存稳定引用，再由带头下载的临时路径显示。HTTP完整非空头像链已通过；原生选择/显示、重新编译恢复已在本轮工具验证，具体证据层级见执行记录。上传成功后的取消/换图/移除不删服务器文件，只有A05成功才改已保存资料；上传/保存失败保留当前草稿并由用户手动重试。资料原生顶部返回有未保存提示；手势返回/退出小程序不在微信该API的拦截范围，草稿不持久保存。已有demo_user原密码未用于本阶段HTTP回归，未猜测、重置或替换。
