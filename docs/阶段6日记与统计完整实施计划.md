## 3. D01～D06和S01实施契约

### 3.1 通用处理

完整路径/api，前端配置已含/api时调用相对路径。登录认证先于日记/统计路径的解析校验；匿名损坏JSON也先401。复用8KiB JSON上限，1000字及20ID完整合法请求须实际核对不误超限。by-date先于/:id。除契约字段外拒绝未知query/body，重复/对象query拒绝；无效输入400 INVALID_INPUT，选择不合法400 INVALID_SELECTION，本人图片引用错误400 INVALID_IMAGE_REF，归属不符/缺失404 NOT_FOUND，不泄露他人记录。

| 接口 | 参数与正常结果 | 重点 |
| --- | --- | --- |
| D01 GET /api/diaries | month必填真实YYYY-MM；data={month,items:DiarySummary[]} | 月首闭/下月首开，日期升序；整月最多31条、不分页，空月[] |
| D02 GET /api/diaries/by-date | date必填真实YYYY-MM-DD；data={diary:DiaryDetail或null} | null是本人该日无记录，不是404；只读不创建 |
| D03 GET /api/diaries/:id | 正整数ID≤4294967295，无额外参数；DiaryDetail | 非本人或不存在404，读完整自身diary_items |
| D04 POST /api/diaries | 完整日记表单；DiaryDetail、201 | 当前用户/服务端时间/真实insertId，日期唯一 |

### 3.2 表单与日期

完整body：wearDate、sourceOutfitId、clothingIds、occasion、mood、photoPath、note。场景trim单行1～20；mood=null或trim单行1～12；note保留换行0～1000 Unicode码点，空串合法。clothingIds为1～20去重有序正整数，全部本人所有，允许归档；sourceOutfitId为本人搭配整数或null，归档仍可来源；photoPath为本人有效稳定路径或null，拒绝TMP/blob/微信临时路径/外部URL。他人来源与缺失同404，不返回他人信息；选择含他人项统一INVALID_SELECTION。完整PUT缺字段拒绝，不静默保留旧值。

DATE合法性同时检查格式/真实日历（闰年、月日范围），可存范围按MySQL DATE常规四位年1000～9999明确限制；month同范围，9999-12月终使用明确末日上界，避免生成不可表示的10000-01-01或把合法月误判。新增/改期只允许不晚于服务器Asia/Shanghai当天。D01/D02可查合法未来日期/月，正常为空；不把仅浏览判为写入日期错误。页面默认服务器当天所属月/当日；客户端显示/选择可用本机日期初值，但最终以服务端为准。S01的asOf可供需要时校准，不新增公共时钟API，客户端误差收到服务端错误就保留表单提示。

正式原生不固定2026-11-06、不固定初选11月5日。历史原型固定日只用于原型，内部注入clock复核2026-11-06的统计；公共API拒绝asOf。不平移任何原演示日记。

### 3.3 事务、唯一冲突与错误结构

入口做一次格式校验；服务层核对归属/存在性，内部信任规范化输入。本人父记录查询带user_id，修改/删除在事务内锁定本人日记行，防止自身写交错；不加版本字段/锁框架/自动重试。一次IN查选中衣物全部归属；来源和照片按现有边界核对。D04事务写主表→按数组1～n写明细→形成响应→提交；D05读本人父→校验来源/选择/图→改主表→删该篇旧明细→插入新明细→提交。D06事务确认本人→删diaries→级联diary_items→提交。失败回滚并释放连接、未知异常交全局500；文件不在数据库事务内。

日期占用可以先查提示，但最后以uq_diaries_user_date唯一约束兜竞争。只将该约束身份对应的重复键映射409 DATE_OCCUPIED，不把任意重复键变409。失败事务先回滚，再用正确当前用户/目标日期查existingDiaryId，保证不残留半写入。异常识别依实际mysql2/MySQL错误证据精确实现，不依赖猜测所有错误文本。不增加自动重试或静默覆盖机制；冲突处理须通过真实竞争用例核对，而非只模拟预检查返回。

DATE_OCCUPIED响应示例（契约示意、不是已运行结果）：{"error":{"code":"DATE_OCCUPIED","message":"该日期已有穿搭日记","details":{"wearDate":"2026-11-05","existingDiaryId":123}}}。BusinessError增加必要details承载并保留现有fields方式；request.RequestError保留error.details供页面使用，原fields调用方不破坏。只扩这一个已承诺错误结构，不建拦截器框架。

客户端D02仅提前提示，不当作不存在的保证。409保留日期、文字、照片稳定路径、选择顺序及来源；可改日继续保存，或点查看/编辑已有篇，跳转前提示放弃草稿，取消则原样留表单；不能暗中合并、覆盖或删除。编辑保持自身日期成功，改到另一篇占用日失败。并发同用户同日双创建必须仅一条成功、一条409；允许两用户同日。
