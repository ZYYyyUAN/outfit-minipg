## 2. A01～A05契约与入口

统一前缀/api；成功为data，失败为error；User只含`id、username、nickname、avatarPath、avatarUrl`。不展开SELECT *到响应，不返回密码、摘要、createdAt等额外字段；id为整数，空头像path/url均为null。

| ID/方法/路径 | 登录 | 请求 | 成功 | 已知失败 |
| --- | --- | --- | --- | --- |
| A01 POST /api/auth/register | 否 | username、password、nickname | 201，data=User；不返回token，不自动登录 | 400 INVALID_INPUT；409 USERNAME_TAKEN |
| A02 POST /api/auth/login | 否 | username、password | 200，data={token,expiresAt,user}；expiresAt为UTC ISO毫秒Z | 400 INVALID_INPUT；401 INVALID_CREDENTIALS |
| A03 POST /api/auth/logout | 是 | 无业务body | 200，data={loggedOut:true} | 401 UNAUTHENTICATED |
| A04 GET /api/me | 是 | 无业务参数 | 200，data=User | 401 UNAUTHENTICATED |
| A05 PUT /api/me | 是 | nickname、avatarPath，两个都显式提交 | 200，data=更新后User | 400 INVALID_INPUT/INVALID_IMAGE_REF；401 UNAUTHENTICATED |

A09保持匿名GET /api/health、200及原data.status=ok，不能要求token或查询数据库。只给已实现的受保护路由挂认证；未实现/api/clothes、/uploads等继续404，不提前注册业务假路由。未知内部故障仍500 INTERNAL_ERROR。

### 2.1 校验和错误

在对应HTTP入口一次检查对象结构、必需字段、类型和允许字段。A01/A02/A05不接收userId、id、passwordHash、authTokenHash、时间或其他额外字段，出现即400；A03仅无body或空对象，不接受非空业务体；A04不接受身份query参数。受保护入口先确认身份，再处理业务参数。内部服务接收已规范化参数，认证归属和磁盘读取作为不同边界核对。

- username：先检查字符串，再trim、转小写；结果仅ASCII字母/数字/下划线，4～20位。规范化在注册和登录一致执行，大小写/外层空白变体仍是同一账号。
- password：字符串，Array.from计8～64字符，不trim、不Unicode归一化、不额外增加强度条件；有边界空格的密码必须原样验证。不得把密码写入错误details或日志。
- nickname：字符串、trim后1～20字符、单行；中文/emoji按字符计，不按UTF-16长度。只在页面显示计数，不静默截断。
- avatarPath：必须显式null或1～255字符字符串；字符串不trim成别的路径，路径语义见第5节。缺失/错误类型400 INVALID_INPUT，结构/归属/文件无效400 INVALID_IMAGE_REF。

JSON解析在路由入口前由Express内置json处理，不增加body-parser依赖。为小表单明确设置8KiB上限；解析失败为400/INVALID_INPUT，超限为413/INVALID_INPUT，details.fields.body给安全原因，不使用图片专用FILE_TOO_LARGE。此传输层补充只新增已有INVALID_INPUT的413场景，实施时在接口说明标明，不新增业务错误码。已知解析错误按type识别，不能把任意SyntaxError都归客户端错误；未知错误仍500。日志不得输出解析器的body、sql、参数、原始错误对象或栈。

业务错误采用一个带status/code/可选fields的错误类型，未知异常交末尾边界。Express 5异步路由返回Promise，由统一边界处理，不给每条服务套大catch。重复注册只将`ER_DUP_ENTRY/1062`且约束身份为`uq_users_username`映射409，其他唯一冲突不得冒充账号重复；数据库唯一约束是最终保证，不用INSERT IGNORE。

## 3. 注册、密码、令牌与资料写入

### 3.1 注册与时间

注册调用共享hashPassword，保存原协议`scrypt$16384$8$1$<盐>$<派生值>`：盐16字节、结果64字节、N16384/r8/p1、178字符。测试只记录格式/长度/正反布尔，不输出完整编码。非法持久编码属于内部数据错误，不静默兼容其他算法。

插入users时显式写规范用户名、昵称、派生值，头像及两登录态列为NULL；同一UTC毫秒时间写created_at和updated_at，返回实际insertId和公开User。单条INSERT无需为形式额外包事务；不创建图片目录、分类或衣橱样例。

### 3.2 登录、认证与退出

登录只按规范用户名取账号并验证密码；未知账号与密码错误均401/INVALID_CREDENTIALS、同一安全提示。失败不写登录态。正确后取一次签发时刻t0，生成32随机字节、转base64url（43字符原令牌），计算SHA-256小写十六进制摘要；到期为t0+7×24小时，更新摘要、到期和updated_at。数据库只保存摘要，响应仅A02根data返回原token；响应/请求采集与断言不得泄露它。

认证入口解析单一Authorization Bearer原令牌：方案名大小写不敏感，原令牌必须43位base64url，拒绝多值/格式错误。查询摘要且`auth_expires_at > 当前UTC时间`，相等已过期，形成`req.auth={userId,tokenHash,...公开资料所需字段}`。不信任body中的身份，不让客户端指定asOf/当前时间。到期用数据库UTC字符串与明确UTC比较，不能把dateStrings结果当本地时间再平移。

退出使用**当前用户ID与当前令牌摘要**限定UPDATE，同时清空摘要和到期、写新的updated_at；受影响0行返回401，不用仅按userId清掉恰好新签发的会话。已过期/被替代/已退出令牌不得退出新会话。无需表锁、分布式锁、会话表或自动重试。

所有鉴权成功请求不自动续期、不更新updated_at。同账号两次成功登录后，前一token调用A03/A04/A05均401；错误登录不影响后一token。

### 3.3 当前资料与允许变更

A04复用本次认证获得的当前资料，返回公开投影，不重复查密码。A05用认证ID更新昵称/头像及updated_at，不能改用户名、密码或登录态；返回本次保存后的完整User。已有头像未显示不代表空头像，UI保存昵称必须保留当前avatarPath。

| 操作 | 允许改变users列 | 不应改变 |
| --- | --- | --- |
| 注册 | 仅新增本次新行，显式生成全部必需值 | 任一既有用户、其他6表、图片 |
| 正确登录/退出 | auth_token_hash、auth_expires_at、updated_at | id、username、password_hash、created_at、nickname、avatar_path |
| 错误登录/A04 | 无 | 所有业务行 |
| A05 | nickname、avatar_path、updated_at | id、username、password_hash、created_at及登录态 |

除专用过期夹具外，所有业务修改通过实际API；不回写旧updated_at或旧token摘要“恢复指纹”。资料隔离只承诺users领域，尚未实现的衣物/搭配/日记/文件接口不计为隔离通过。

## 4. request、会话与导航

### 4.1 模块分工

`utils/session.js`持有当前token、expiresAt、内存User、递增sessionEpoch及单次登录导航状态，不依赖request。`utils/request.js`依赖config/session，负责一次wx.request及协议边界。App使用两者建立authReady恢复过程；页面只调用入口，不各自读写storage或拼认证头，避免循环依赖。

storage只保存一个本项目版本化登录键中的token和expiresAt；User在内存，启动调用A04恢复。密码、头像临时文件和业务集合不进入storage。清理只移除本项目登录键及其内存资料/页面用户状态，不wx.clearStorage抹掉无关数据。

request约定相对API路径，如`/auth/login`和`/me`；config已含/api，内部只拼一次，不同时兼容完整/api路径或任意外部URL。默认auth=true；注册、登录、健康显式auth=false且不附Authorization。统一返回Promise<data>，失败reject一个客户端错误类型，含code/message/可选httpStatus和fields；不混用null、返回error对象和抛异常。

默认timeout=5000ms。检查HTTP状态和JSON封装后才判成功，2xx错误形状为本地INVALID_RESPONSE；网络拒绝/超时为本地NETWORK_ERROR/TIMEOUT。它们不是新增服务器业务码，不清token、不冒充401，也不自动重试POST/PUT。

### 4.2 401与迟到响应

- A02的401/INVALID_CREDENTIALS：留登录表单显示账号或密码错误，不触发全局清理/跳转，不输出是否存在该账号。
- 受保护请求401/UNAUTHENTICATED：仅当该请求所带token/epoch仍对应当前会话时清本机登录态并进入登录页；不同code的其他错误按协议显示，不统一误判为过期。
- 采纳新登录、退出或主动失效时递增epoch；受保护请求发出时捕获epoch，回包发现已变化则拒绝为本地STALE_SESSION，不覆盖新User或清除新会话。旧页面忽略此类结果，不提示旧账号错误。
- 同会话多个401只执行一次清理和reLaunch；导航完成后释放单次导航标记。一次登录请求也在采纳结果前核对页面仍有效和发起会话未变，防止离开页面后迟到回包更换身份。

不建设通用取消队列或拦截器框架；少量会话版本与导航标记服务明确的跨账号场景。关键竞争用可控回调测试，不通过重复人工登录碰运气。

### 4.3 首开与状态恢复

将登录页设为app.json首个普通页，四tab定义不变。App只初始化单次authReady并按保存token调用A04，不在onLaunch尚无页面时直接反复导航。登录页等待恢复：

| 状态 | 行为 |
| --- | --- |
| 无token | 展示登录表单，不发认证请求 |
| token经A04确认有效 | User进内存，switchTab衣橱；我的页显示真实资料 |
| A04明确401 | 清本机登录键，留登录页说明状态失效 |
| 网络/服务错误 | 保留token，不把无法联网当已退出；显示恢复失败和手动重试，不先展示旧账号资料或允许伪登录进入 |

四tab及资料页onShow等待authReady，再执行一个统一登录守卫；未登录reLaunch登录，不堆叠多层登录页。登录后进入衣橱，不支持任意外部returnUrl。我的页显示时可重新A04确认资料/登录态，其他业务占位页不伪造数据请求。重新编译/重开仍通过A04恢复，客户端到期信息仅作提示，最终身份由服务端判定。

注册成功返回登录页，预填规范用户名；不复制密码到登录页、不自动持久登录。退出仅A03确认loggedOut=true后清本地状态并reLaunch登录。网络/500失败则留当前会话和页面，显示“退出未确认，请重试”，不弹退出成功；A03若401则按失效处理，不称成功撤销。切换账号走确认退出→登录另一账号，不单独新增账户切换系统。

## 5. 头像引用与P3-03接口

A05的头像引用校验在本阶段实现，文件显示与上传不实现。null直接映射null URL；非空路径须严格为当前认证ID的`users/<十进制ID>/<UUID>.jpg或.png`，1～255字符，不接受反斜杠、父目录、编码绕行、绝对路径、URL、TMP、blob或wxfile等临时地址。目录ID与认证ID比较，不由客户端任意指定。

在配置的UPLOAD_ROOT下解析并确认路径仍在当前用户目录，文件为存在的普通文件、扩展名/图片签名一致。路径/不存在/跨用户等均400 INVALID_IMAGE_REF，不泄露对方目录是否存在。不增加图片表或复制文件，不删除旧头像引用的文件；上传可解码、大小限制及鉴权读取由P3-03完整实现验证。

公开User的avatarUrl为origin+'/api/media/'+filename，URL不入库。P3-03前该读取路由尚不可用，UI不直接把鉴权URL作为image src，不静态公开文件。我的/资料页用本地图形或文字占位，并明确图片功能待接入；保存昵称原样带回当前avatarPath，不因占位图清空它。已有非空路径时可提供“移除头像（保存后生效）”，仅改变草稿为null；没有头像时不放假选择/上传按钮。

验证分层：

1. 真实HTTP必须覆盖null保存、缺字段/错误类型、跨用户/外部/临时/穿越/不存在路径拒绝；被拒绝时资料不变。
2. 合法非空引用的只读函数正例使用既有文件的**真实归属ID**（从正式映射读取），不能把演示图片作为测试账号A的合法文件。它只证明路径/文件验证，不冒充该用户已HTTP登录；也可使用测试临时目录的小型PNG夹具，清理仅限本次夹具，不写uploads。
3. DTO映射和资料服务对合法非空路径的分支通过单元/受控集成检查；非空头像完整HTTP保存及实际显示在P3-03给专用账号上传文件后联验。P3-02结束记录必须明确该待测正例，不把函数验证写成HTTP端到端通过。

若实施时有演示用户原密码且用户愿意在本机提供，可实际验证其登录/A04/退出与旧编码兼容；不要求为本阶段改演示昵称/头像或回写旧令牌。没有私有密码时不猜、不重设，已有演示账号正确凭据HTTP回归列为待验证，不用新账号冒充；同协议已知密码夹具和新注册账号的真实登录验证本阶段编码实现。

### 7.1 数据和账号计划

实施前只读记录实际U0用户集合/非敏感公开字段，私有字段只在内存做指纹；冻结其他6表全部行/结构、50图及历史文件。新账号不复制任何业务行或建图片目录。

### 7.2 过期、隔离与验证层次

- 过期真实HTTP：仅对本轮manifest已确认新建的A账号、当前摘要匹配的行，将expires_at显式设到过去，摘要仍非NULL以符合成对约束，再A04/A05/A03验证401；随后正常登录并退出，清空本轮测试会话。不改已有账号、不改全局或会话时钟、不加公开测试接口。此唯一SQL夹具UPDATE记录行ID/字段/时间和影响行数，不记录摘要值。
- 精确到期边界：认证时间比较函数用受控now测试到期前1ms有效、相等及后1ms无效；真实HTTP过期测试另留证，不混为一种结果。
- 双账号：A/B分别登录，A04只返回各自公开资料；A05改A昵称，B不变；body传B的userId、改用户名等被拒绝，不能跨账号更新。两个账号可各有独立有效token，同账号新登录才覆盖旧会话。
- 单会话：A连续登录两次，旧token全拒绝且不能退出新会话；错误密码尝试不影响新token；注销后重放失败，重启服务器有效token仍可读取且到期不延长。
- 前端：用受控wx.request回调模拟旧A成功/401晚于B登录、多个401及登录页卸载，核对新状态不被误清；真实工具再验证基本切换/恢复。回调夹具不是工具真实网络证据。

所有日志仅记录布尔、长度、状态码/业务码、非敏感User及字段变化名。完整token/摘要/密码/用户整行不输出；尤其不能用失败的deepEqual把A02全响应或密码派生值打印到测试报告。
