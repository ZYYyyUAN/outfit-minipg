### 3.1 schema.sql的边界

未来创建`database/schema.sql`，UTF-8保存，仅含必要注释、身份/环境只读输出、项目库创建/选择及7表DDL。固定目标wardrobe_demo，不接收动态库名或任意SQL片段。

| CHECK_CONSTRAINTS | 7个表达式的列、操作符、边界及枚举成员，与所属表/ENFORCED联合核对 |
| TRIGGERS、ROUTINES、EVENTS | 没有意外增加的辅助对象，不靠存储过程模拟测试 |

元数据期望在验证脚本内集中表达，来自已审查的数据库设计；不从“当前真实库”反向生成期望后自证正确，也不只从同一schema.sql派生预期而遗漏对文档的核对。无需单独再建一套庞大schema配置框架。

比较规则：

- int与integer、正常显示宽度和大小写可规范化；但不能忽略UNSIGNED、长度、顺序、精度、NOT NULL或额外属性。
- nullable列的默认NULL展示与SHOW CREATE的显式写法可以等价；NOT NULL必填列应无默认。DEFAULT空字符串/0必须分别辨认，不能把NULL当空字符串。
- DATETIME必须精度3，EXTRA不可出现自动DEFAULT_GENERATED/ON UPDATE；4个主实体ID才有auto_increment。分类和两明细不可多出ID。
- CHECK仅规范化反引号、冗余括号、空白和MySQL正常字符集引导形式；对枚举集合、比较符、AND/OR、NULL判断必须核对语义，不采用删掉所有符号后比较的办法。只处理本项目7个已知表达式，不写通用SQL解析器。
- RESTRICT与MySQL无延迟约束下等价的NO ACTION展示需要结合实际声明说明；最终DDL仍显式RESTRICT，唯一CASCADE不可被归一化掉。
- AUTO_INCREMENT下一值不作为结构相等条件。精确索引列序和前缀仍必须一致，不能只检查索引数量。

产出按表/字段/约束列出expected、actual、status和差异；缺任何字段或存在额外对象均失败。元数据不可见或查询失败是未验证/失败，不当作“没对象所以匹配”。

## 6. 临时夹具、事务和错误约定

### 6.1 夹具规模与标识

在7表已确认全空后，一条非池化连接开始一个外层事务。建立2名临时用户A/B、1个临时分类K、3件衣物C1/C2/C3、1套搭配O1及其2条明细、3篇日记D1/D2/D3及各自明细。D1为A的2026-11-05，D2为A的2026-11-04，D3为B的2026-11-05；A的两篇可引用O1，实际明细独立插入。用户归属选择一致，不用它来伪证FK会隔离用户。

username和分类名称以p202加runId短后缀区分；分类id在VARCHAR16内，sort_order取合法值1。测试分类不是tops等正式分类导入，测试用户password_hash仅为明显的测试占位值，非真实账号密码或可用scrypt凭据。文件字段为长度合法的测试相对路径，不复制文件、不验证磁盘/图片归属。

4类自增实体均读取实际insertId并在内存保存，用户及父记录按依赖顺序插入，不能假定ID为1/2或与样例后缀相同。时间字段显式固定UTC毫秒值，可空状态按设计使用NULL，备注使用空字符串。

每个B用例在共同夹具上创建SAVEPOINT，动作及观测完成后ROLLBACK TO并释放该保存点，恢复相同基线。某个用例需要额外行时只在其保存点内创建，不把夹具变化传给下一用例。不在外层事务中再次START TRANSACTION，也不混入DDL或任何会隐式提交的操作。

### 6.2 预期失败识别

| 失败类别 | 目标MySQL8.0预期身份 | 核对方法 |
| --- | --- | --- |
| 主/唯一重复 | errno1062，ER_DUP_ENTRY，SQLSTATE23000 | 核对当前表的PRIMARY或指定uq名称，再读取原行确认未被覆盖 |
| 插入/更新无父引用 | errno1452，ER_NO_REFERENCED_ROW_2，23000 | 对应明确fk名称；其余字段合法，不能让长度/重复位置先失败 |
| RESTRICT父删除 | errno1451，ER_ROW_IS_REFERENCED_2，23000 | 隔离目标关联后确认fk名称及父子行仍存在 |
| CHECK失败 | errno3819，ER_CHECK_CONSTRAINT_VIOLATED，HY000 | 必须对应ck名称；使用在列类型范围内但违反CHECK的值 |
| 必填显式NULL | errno1048，ER_BAD_NULL_ERROR，23000 | 确认所测列；不能将其他输入错误当作NULL测试通过 |

预期错误仅捕获当前语句。若实际错误身份不同，保留脱敏code/errno/sqlState和约束名，将用例判失败，不靠“发生了任意错误”通过。错误中表名/约束名可用于核对；不输出完整连接对象、密码、认证哈希或任意SQL插值。

归档测试用2，分类排序用0/8，明细顺序用0，均在各自UNSIGNED存储范围内，避免负数先被范围错误拒绝而没有验证到CHECK。无效FK选择已确认不存在且在合法类型范围内的父ID/分类键；其他字段和位置保持合法。

### 6.3 外层回滚和异常结束

所有B用例结束后无条件ROLLBACK外层事务，再在同一连接读取7表COUNT(*)；关闭后另建只读连接复查COUNT(*)，应全部为0，核对无p202测试标识。记录开始/结束行数，不能用TABLE_ROWS估计替代。

用例未知错误或断言失败即停止后续用例，在事务资源边界finally明确回滚并关闭。正常SQL失败通常只回滚当前语句，不等于整个夹具自动消失。连接意外断开时该事务由InnoDB回滚，执行者仍需重连只读确认；若无法重连，本轮结果为未完成，不凭推断宣布无残留。失败后不得用DELETE/TRUNCATE或关闭FK清理，也不自动重试用例。

自增分配值即使回滚也可能不回收；验收要求无测试行，不要求下一值恢复1。保存4个自增表的前后下一值作为观察，不执行ALTER TABLE AUTO_INCREMENT重置。P2-03只使用实际insertId映射。

### 10.3 官方依据及验证边界

本轮查阅的官方文档用于规划，不是本机DDL/DML实测：

- [MySQL8.0隐式提交](https://dev.mysql.com/doc/refman/8.0/en/implicit-commit.html)：建表等DDL不能按夹具DML的事务回滚方式恢复，多条DDL失败可能已留下成功对象。
- [InnoDB自增处理](https://dev.mysql.com/doc/refman/8.0/en/innodb-auto-increment-handling.html)：已分配的自增值即使事务回滚也可能不回收，允许空缺。
- [CHECK约束](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html)：表达式/ENFORCED要求，不用当前日期函数或子查询CHECK替代业务校验；实际执行情况需P2-02验证。
- [InnoDB错误处理](https://dev.mysql.com/doc/refman/8.0/en/innodb-error-handling.html)：重复键等错误通常仅撤销当前语句，测试器必须明确回滚外层事务。
- [mysql客户端选项](https://dev.mysql.com/doc/refman/8.0/en/mysql-command-options.html)及[服务端错误参考](https://dev.mysql.com/doc/mysql-errors/8.0/en/server-error-reference.html)：批量执行不加--force；预期失败按errno/SQLSTATE及约束身份核对。
- [MySQL2官方文档](https://sidorares.github.io/node-mysql2/docs)：离线核对采用Promise连接和参数化查询，实际驱动/Node组合留实施时核对。
