# 个人衣橱与穿搭日记执行计划

制定日期：2026年11月6日。按阶段验收推进，不设置固定交付日期。当前处于素材与方案准备完成、业务开发尚未开始的状态。

## 目标与范围

完成可在微信开发者工具本地演示的微信小程序，技术栈为原生微信小程序、JavaScript、Node.js Express、MySQL。底部入口为衣橱、搭配、日记、我的；实现10个数据库业务页面，注册、登录和个人资料页面另计。

以韩系日常女装为视觉基线，使用现有24件衣物、8套搭配和12篇虚构日记。不把继续搜集素材作为开发前置条件。校园甜美风在页面原型完成后按展示缺口少量补充，建议最多4～6件，并同步更新来源和演示数据。

首版围绕衣物管理、手动搭配、穿搭日记和统计；AI推荐、自动抠图、虚拟试衣、商城、天气和公网部署不纳入当前交付范围。

## 页面验收清单

1. 衣橱列表：查询与多条件筛选。
2. 衣物详情：衣物属性、相关搭配及穿着历史。
3. 衣物新增与编辑：上传、维护资料。
4. 搭配列表：查询与场景筛选。
5. 搭配详情：查看组合、编辑及记录穿着。
6. 搭配新增与编辑：选择衣物、维护组合及顺序。
7. 穿搭日历：切换月份、选择日期查看记录。
8. 日记详情：当次衣物、文字、心情及可选照片。
9. 日记新增与编辑：补记、修改及删除。
10. 衣橱统计：类别分布、月度记录天数、常穿和近期未穿。

## 必须验证的业务规则

- 用户隔离：两名测试用户不能查看或修改对方衣物、搭配、日记和上传文件。
- 日记唯一：数据库约束与页面行为均保证每人每天最多一篇，可编辑已有记录。
- 历史独立：创建日记后再修改来源搭配，旧日记的衣物集合保持不变；用户主动编辑日记才更新该记录。首版不保存衣物名称和图片的历史版本。
- 归档保留关系：归档衣物或搭配不会让旧日记中的关联丢失。
- 统计来自日记：保存搭配不计入穿着；同衣物同日只计一次；改记、删记后统计与实际记录一致。
- 近期未穿：统计当前用户未归档衣物中最近30天无日记关联的衣物，包含从未记录穿着的衣物。
- 图片持久化：上传后的文件由本地后端提供访问地址；微信临时文件路径不作为持久地址；小程序主包不携带全部原图。

测试优先覆盖这些业务行为和完整操作流程，不为低影响的样式调整编写重复实现的测试。
